##  Задание 1
Задание 1. СУБД
Кейс
Крупная строительная компания, которая также занимается проектированием и девелопментом, решила создать правильную архитектуру для работы с данными. Ниже представлены задачи, которые необходимо решить для каждой предметной области.

Какие типы СУБД, на ваш взгляд, лучше всего подойдут для решения этих задач и почему?
1.1. Бюджетирование проектов с дальнейшим формированием финансовых аналитических отчётов и прогнозирования рисков. СУБД должна гарантировать целостность и чёткую структуру данных.
1.2. Под каждый девелоперский проект создаётся отдельный лендинг, и все данные по лидам стекаются в CRM к маркетологам и менеджерам по продажам. Какой тип СУБД лучше использовать для лендингов и для CRM? СУБД должны быть гибкими и быстрыми.
1.3. Отдел контроля качества решил создать базу по корпоративным нормам и правилам, обучающему материалу и так далее, сформированную согласно структуре компании. СУБД должна иметь простую и понятную структуру.
1.4. Департамент логистики нуждается в решении задач по быстрому формированию маршрутов доставки материалов по объектам и распределению курьеров по маршрутам с доставкой документов. СУБД должна уметь быстро работать со связями.

# Ответ
1.1. Бюджетирование проектов, финансовая аналитика и прогнозирование рисков
Рекомендуемый тип СУБД: реляционная СУБД (SQL)
Примеры: PostgreSQL, Oracle Database, Microsoft SQL Server.
Почему:
гарантирует целостность данных через ACID-транзакции;
поддерживает строгую схему данных;
обеспечивает надежную работу с финансовыми операциями;
позволяет строить сложные аналитические отчёты с помощью SQL;
удобна для последующего создания хранилищ данных и BI-аналитики.

1.2. Лендинги и CRM
Для лендингов
Рекомендуемый тип СУБД: документо-ориентированная NoSQL СУБД
Пример: MongoDB.
Почему:
структура лендингов может часто меняться;
удобно хранить различный контент в формате JSON-документов;
высокая скорость записи и чтения;
легко масштабируется при росте посещаемости.
Для CRM
Рекомендуемый тип СУБД: реляционная СУБД (возможно в сочетании с NoSQL)
Примеры: PostgreSQL, MySQL.
Почему:
данные о клиентах имеют чёткие связи (лид → сделка → клиент → менеджер);
необходима целостность данных;
требуется выполнение сложных выборок и отчётов.

1.3. База корпоративных норм, регламентов и обучающих материалов
Рекомендуемый тип СУБД: документо-ориентированная СУБД
Пример: MongoDB.
Почему:
документы могут иметь разную структуру;
удобно хранить инструкции, регламенты, статьи и методические материалы;
легко организовать иерархию разделов и подразделов;
простое масштабирование базы знаний.
Также возможно использование реляционной СУБД, если структура материалов строго фиксирована, однако для корпоративной базы знаний документо-ориентированный подход обычно удобнее.

1.4. Логистика: маршруты доставки и распределение курьеров
Рекомендуемый тип СУБД: графовая СУБД
Примеры: Neo4j, ArangoDB.
Почему:
объекты, склады, дороги и курьеры естественно представляются в виде графа;
эффективно выполняется поиск кратчайшего пути;
быстро обрабатываются сложные связи между узлами;
хорошо подходит для задач маршрутизации и оптимизации логистики.



##  Задание 2
2.1. Пользователь пополняет баланс счёта телефона, распишите пошагово, какие действия должны произойти для того, чтобы транзакция завершилась успешно. Ориентируйтесь на шесть действий.

# Ответ

2.1. Пополнение баланса телефона: шаги успешной транзакции
Рассмотрим процесс пополнения баланса мобильного телефона через банковскую карту.
Пользователь вводит данные платежа
Указывает номер телефона и сумму пополнения.
Система проверяет корректность введённых данных.
Создание транзакции
В базе данных создаётся запись о новой транзакции со статусом «В обработке».
Система резервирует необходимую сумму на счёте пользователя.
Проверка возможности списания средств
Платёжная система или банк проверяет наличие достаточного количества средств на карте/счёте.
Если средств недостаточно, транзакция отклоняется и выполняется откат операции.
Списание денежных средств
После успешной проверки банк списывает указанную сумму со счёта плательщика.
Информация о списании передаётся оператору связи.
Зачисление средств на баланс телефона
Оператор связи увеличивает баланс указанного номера телефона на сумму платежа.
В базе данных обновляется информация о балансе абонента.
Фиксация транзакции (COMMIT)
Статус транзакции изменяется на «Успешно выполнена».
Пользователь получает подтверждение об успешном пополнении (SMS, push-уведомление или сообщение на экране).
Все изменения окончательно сохраняются в базе данных.
Если на любом этапе возникает ошибка (например, недостаточно средств, сбой связи с оператором или ошибка записи в БД), выполняется ROLLBACK — отмена всех изменений, и система возвращается в исходное состояние. Это обеспечивает соблюдение принципов транзакций (ACID).

##  Задание 3
Задание 3. SQL vs NoSQL
3.1. Напишите пять преимуществ SQL-систем по отношению к NoSQL.

# Ответ
Гарантия целостности данных (ACID-транзакции)
SQL-СУБД поддерживают принципы ACID (атомарность, согласованность, изолированность, долговечность).
Это особенно важно для финансовых операций, банковских систем и бухгалтерии.
Строгая структура данных
Данные хранятся по заранее определённой схеме (таблицы, поля, типы данных).
Это снижает вероятность ошибок и упрощает контроль качества данных.
Поддержка сложных запросов
SQL предоставляет мощный язык запросов для фильтрации, агрегации, сортировки и анализа данных.
Можно легко выполнять сложные аналитические запросы с использованием JOIN, GROUP BY, подзапросов и других механизмов.
Эффективная работа со связями между данными
Реляционные базы данных специально разработаны для хранения связанных сущностей.
Внешние ключи и операции JOIN позволяют удобно работать с отношениями между таблицами.
Высокая зрелость и стандартизация
SQL является международным стандартом и поддерживается большинством реляционных СУБД.
Существует большое количество инструментов, документации, специалистов и готовых решений для администрирования и аналитики.


##  Задание 4
Необходимо производить большое количество вычислений при работе с огромным количеством данных, под эту задачу выделено 1000 машин. На основе какого критерия будете выбирать тип СУБД и какая модель распределённых вычислений здесь справится лучше всего и почему?

# Ответ
Для обработки огромных объёмов данных на кластере из 1000 машин целесообразно использовать распределённую NoSQL-СУБД, а в качестве модели распределённых вычислений — MapReduce, поскольку она обеспечивает высокую степень параллелизма, масштабируемость и отказоустойчивость при работе с Big Data.
